# Drift predictor scripts

This folder contains the drift-model pipeline for the zeta analysis project. The code is organized around a two-stage workflow:

1. Generate rich zero-level feature tables from the zeta zero list.
2. Use those features to test whether phase drift is predictively driven by frequency drift and to summarize the result in a public-facing JSON report.

The scripts here are research-oriented and rely on a set of generated CSVs and local input paths. Several of the files still contain placeholder paths such as `your_path` and must be updated before running them on real data.

## Workflow overview

The intended operational flow is:

1. Run `feature_generator_v6.py`
   - Reads `zeros1.txt`
   - Computes a large feature table for many zeta zeros
   - Saves `zeta_features_v6_10000.csv`

2. Run `driftmodel_public.py`
   - Loads `zeta_features_v6_10000.csv`
   - Builds the phase/frequency drift analysis
   - Defines anchor geometries and evaluates persistence vs. frozen and trend baselines
   - Saves `public_driftmodel.json`

## Script overview

### 1) `feature_generator_v6.py`
Purpose:
- Generates a zero-by-zero feature table for the drift-model analysis.
- Builds features before any zero detection step, to avoid leakage from `t_detected` or `delta_actual`.
- Produces a high-dimensional dataset intended for downstream drift modeling.

Inputs:
- `zeros1.txt` from the project data directory
- Paths are currently set through the `CONFIG` dictionary and placeholder strings such as `your_path\zeros1.txt`

Outputs:
- `zeta_features_v6_10000.csv`
- `zeta_features_v6_10000_summary.json`

Key behavior:
- Computes the full Duffing trajectory for each zero using fixed model parameters:
  - `ALPHA = 12.89`
  - `BETA = 370.92`
  - `GAMMA = 0.4811`
  - `LAM_OPT = 112.4`
  - `PHI_OPT = 2.035`
- Extracts features from multiple sources:
  - multiscale temporal features
  - spectral features
  - resonance features
  - stability features
  - geometry features
- Uses a separate detection pass after features are computed

Typical usage:
```bash
python src/drift_predictor/feature_generator_v6.py
```

Notes:
- This script is computationally expensive and is intended for a large dataset (configured for 10,000 zeros).
- The file is designed to preserve zero leakage guarantees: all features are computed at `t_known` before the actual detection step.
- It writes CSV output for direct use by the drift analysis model.

### 2) `driftmodel_public.py`
Purpose:
- Implements the public drift analysis stage.
- Tests whether phase drift follows frequency drift under a causal, forward-only EKF setup.
- Evaluates multiple predictors across anchor geometries and horizons.
- Produces a public JSON summary with statistical results and caveats.

Inputs:
- `zeta_features_v6_10000.csv`
- Requires a real data path in the script configuration (`base_dir`, `output_dir`, and `csv_path`)

Outputs:
- `public_driftmodel.json`

Key behavior:
- Loads the generated feature table and computes `log_t` and geometric cluster structure.
- Uses a K-means grid to define spatial anchor geometries.
- Constructs the observed relative phase and drift relations from the data.
- Runs an Extended Kalman Filter (EKF) for phase tracking.
- Evaluates the following predictors:
  - `PERSIST`
  - `FROZEN`
  - `TREND`
  - `ORACLE_A`
- Computes moving-block bootstrap summaries for the difference in performance.
- Produces a JSON summary with:
  - `summary`
  - `boot`
  - `per_anchor`
  - `anchor_positions`
  - `documented_caveats`
  - `replication_chain`

Typical usage:
```bash
python src/drift_predictor/driftmodel_public.py
```

Notes:
- This script is the main analysis engine of the folder.
- It is explicitly built around the claim that phase drift is coupled to frequency drift rather than requiring an additional interaction term.
- The public JSON contains both the statistical results and the methodological caveats required for interpretation.

## Expected data files

The main dataset expected by the drift pipeline is:

- `zeta_features_v6_10000.csv`

This file is generated by `feature_generator_v6.py` and is then read by `driftmodel_public.py`.

The zero-list input used by the feature generator is:

- `zeros1.txt`

This is expected to contain the zeta zero values used to build the feature dataset.

## Typical execution order

```bash
python src/drift_predictor/feature_generator_v6.py
python src/drift_predictor/driftmodel_public.py
```

This sequence matches the project’s design:
- generate the feature table
- evaluate the drift model against the phase/frequency dynamics
- export the public summary JSON

## Output interpretations

The key outputs are:

- `zeta_features_v6_10000.csv`: the full raw feature matrix used for drift analysis
- `zeta_features_v6_10000_summary.json`: summary of the generated feature set
- `public_driftmodel.json`: final analytical report with scores, bootstraps, anchor diagnostics, and caveats

## Summary

This folder contains the phase-drift modeling pipeline for the zeta project. It combines:

- large-scale feature engineering,
- EKF-based phase tracking,
- anchor-geometry evaluation,
- moving-block bootstrap inference,
- and a public model report.

The feature generator builds the large dataset; the drift model interprets it in terms of causal phase/frequency coupling and exports a detailed public summary.
