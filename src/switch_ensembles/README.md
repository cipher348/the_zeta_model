# Switch Ensembles

This folder contains scripts for generating and analyzing transition/switch ensembles associated with partial Dirichlet sums. The scripts use CSV/CSV.GZ files as hand-off points; the filenames below are the relevant dependencies (the scripts do not require a particular folder layout).

## Data flow and file dependencies

```text
Odlyzko zeta-zero table (zeros6.txt; external input)
                  |
                  v
zeta_transition_operator_full.py --gzip
  writes zt_full_switches.csv.gz and zt_full_matches.csv.gz
                  |
       +----------+----------------+------------------+
       |                           |                  |
       v                           v                  v
s27_e1a_surrogate.py     s28_org0_coincidence.py   s29_deficit_redistribution.py
  reads switches           reads switches           reads switches
  writes profiles + tests   writes coincidence CSV   writes CSV, bands, log
       |                           |
       v                           v
s27_throne_check.py <-------+  s28_xi_split3.py
  reads switches + profiles    reads switches; optionally reads coincidence CSV

s30_grid_td.py is independent of these files: it computes its grid scan directly
and writes s30_grid_td.csv and s30_grid_td_log.txt.
```

### Inputs and outputs by script

| Script | Reads | Writes |
|---|---|---|
| `zeta_transition_operator_full.py` | `zeros6.txt` by default; override with `--zeros` | `zt_full_switches.csv.gz` and `zt_full_matches.csv.gz` when run with `--gzip` and the default `--out-prefix zt_full` |
| `s27_e1a_surrogate.py` | `zt_full_switches.csv.gz` by default; override with `--switches` | `s27_e1a_profiles.csv`, `s27_e1a_tests.csv` |
| `s27_throne_check.py` | `zt_full_switches.csv.gz`; `s27_e1a_profiles.csv` (optional at runtime) | `s27_throne_check.csv` |
| `s28_org0_coincidence.py` | `zt_full_switches.csv.gz` by default; override with `--switches` | `s28_org0_coincidence.csv` |
| `s28_xi_split3.py` | Switches file via `--switches`; optionally `s28_org0_coincidence.csv` via `--coincidence-csv` | `s28_xi_split3.csv` |
| `s29_deficit_redistribution.py` | `zt_full_switches.csv.gz` by default; override with `--path` | `s29_deficit_redistribution_left.csv` (or `_max.csv`), corresponding `_bands.csv` and `_log.txt` |
| `s30_grid_td.py` | No data-file input | `s30_grid_td.csv`, `s30_grid_td_log.txt` |

**Important run-order and filename notes**

- `zeros6.txt` is an external input, not generated by a script in this folder. It is the Odlyzko zeta-zero data source used to set the scan interval and to match detected switches to zeros. The project README cites Odlyzko's *Tables of zeros of the Riemann zeta function* and links to [the Odlyzko zeta tables](https://www-users.cse.umn.edu/~odlyzko/zeta_tables/index.html). The file is called `zeros6.txt` (with the final “s”).
- To generate the compressed switch file expected by the downstream scripts, run the transition-operator script with `--gzip` (for example: `python zeta_transition_operator_full.py --zeros zeros6.txt --out-prefix zt_full --gzip`). Without `--gzip`, it writes `.csv`, not `.csv.gz`.
- `s27_e1a_surrogate.py` produces the profiles consumed by `s27_throne_check.py`; run the surrogate first if you want the empirical profile comparison. The profile read is optional in the throne-check script: if missing, it warns and continues without that comparison.
- `s28_org0_coincidence.py` produces the optional coincidence CSV consumed by `s28_xi_split3.py` when `--coincidence-csv s28_org0_coincidence.csv` is supplied.
- `s28_xi_split3.py` has a machine-specific absolute Windows path as its default `--switches` value. Pass the intended switch filename explicitly when running elsewhere. The dependency table follows filenames as requested; a path override may still be needed operationally.
- Mentions of other analyses in comments/docstrings (for example, `s26_ndeep_audit.csv`) are references only; this folder's scripts do not read those files as runtime inputs.

## Mathematical structure

### 1. Partial Dirichlet-sum walk and switch catalog

The primary object is the finite Dirichlet sum

\[
P_k(t)=\sum_{n=1}^{k} n^{-\sigma}e^{-it\log n},
\qquad \sigma=\tfrac12\text{ by default},
\]

with the minimizing index chosen over `k = 3, ..., 200` by default:

\[
k^*(t)=\underset{3\le k\le 200}{\arg\min}\,|P_k(t)|.
\]

`zeta_transition_operator_full.py` builds a base t-grid across the interval determined by the zero table (with configurable margins), detects changes in the minimizing index, refines each candidate transition, and verifies that the minimizing index differs immediately on the two sides. Each accepted event records its time, left/right minimizing indices, adjacency indicator, residual, and verification flag. The principal output is the switch catalog. The matches output associates catalog switches with the nearest supplied zero and records normalized offsets.

### 2. Prime-phase randomized surrogate and dyadic component

`s27_e1a_surrogate.py` holds the event times fixed and assigns each integer term a multiplicative phase:

\[
\psi_j=\sum_{p\le 200}\nu_p(j)\theta_p,\qquad
P_k^{(\theta)}(t)=\sum_{j\le k}j^{-1/2}e^{-it\log j}e^{i\psi_j},
\]

where `\nu_p(j)` is the exponent of prime `p` in `j`, and the prime phases are independently sampled uniformly on `[0, 2π)`. The `EMP` run sets all phases to zero; additional `SUR-*` runs randomize them. The construction preserves each term's magnitude and the multiplicative phase relations (including the dyadic sequence `\psi_{2^m}=m\theta_2`) while disrupting cross-prime phase alignment.

For each run, the script recomputes the minimizing index and measures the residual after separating the dyadic terms `2^m` from the other term families (the unit term, odd primes, odd composites, and even composites). It writes band-level profiles and test summaries. `s27_throne_check.py` independently recomputes a walk and compares its dyadic-ladder prediction with the empirical `L` profile from the surrogate output. Its ladder prediction is

\[
L_{\mathrm{pred}}(M,\phi)=\left|\sum_{m=1}^{M}2^{-m/2}e^{im\phi}\right|,
\qquad M=\lfloor\log_2 k^*\rfloor,
\]

with phase bands formed from the distance of the second-harmonic phase to 0 degrees.

### 3. Grid-versus-production coincidence analysis

`s28_org0_coincidence.py` independently recomputes the unrandomized (`θ=0`) minimizing-index walk on a uniform grid over `[20, 10,000]`. It compares grid transitions with production-catalog transitions in the same interval using a time tolerance of `dt/2`, and records time overlap and agreement of the left/right indices. It writes the resulting comparison table for optional coverage analysis in `s28_xi_split3.py`.

### 4. Jump-size, phase-world, and residual diagnostics

The S28/S29 analyses classify transitions by jump size `|k_right-k_left|`: `1`, `2`, `3–4`, `5–8`, and `>8`. They also assign each event to a phase region using a folded phase distance, distinguishing polar (`≤20°` for S29), middle, and pi (`≥150°`) regions where applicable. `s28_xi_split3.py` focuses on high-index (`k_left ≥ 128`) events, relative residuals, and dyadic contributions, and can optionally assess whether events fall in intervals covered by grid transitions.

`s29_deficit_redistribution.py` reports jump-category shares across phase regions and frames, including a `[20, 10,000]` window and an `M≥4` restriction (`M = floor(log2 k*)`). It compares the adjacent share with the `>8` share and reports their bandwise correlation; these are diagnostics, not an assertion that the categories are exact complements.

### 5. Independent grid detector

`s30_grid_td.py` computes the same `P_k(t)` minimizer directly on a uniform grid, without using the production switch catalog. It flags changes in `k*` between neighboring grid points and accumulates jump categories, phase-region rates, phase bands, and `M`-matched comparisons. This makes its computation independent of the catalog files; its CSV and log are outputs only.

## Suggested execution order

```bash
python zeta_transition_operator_full.py --zeros zeros6.txt --out-prefix zt_full --gzip
python s27_e1a_surrogate.py --switches zt_full_switches.csv.gz --seeds 4
python s27_throne_check.py --switches zt_full_switches.csv.gz --profiles s27_e1a_profiles.csv
python s28_org0_coincidence.py --switches zt_full_switches.csv.gz
python s28_xi_split3.py --switches zt_full_switches.csv.gz --coincidence-csv s28_org0_coincidence.csv
python s29_deficit_redistribution.py --path zt_full_switches.csv.gz
python s30_grid_td.py
```

The full transition scan and the analysis scripts can be computationally intensive. Use each script's help/options and smoke-test options before a full run.
